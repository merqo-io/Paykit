# @merqo/ui login gaps (paykit pilot)

paykit's `/login` renders `AuthShell` and `LoginForm` from `@merqo/ui` v0.46.0.
Every sign-in behaviour is kept. This lists where the shared components fall
short, so the other five kits know what to expect before they adopt them. Each
"smallest change" is a prop or type on `@merqo/ui`.

## Not a gap

- `?mode=signup` from the landing page is `defaultMode`.
- The MFA hand-off, redirect after sign-in and `next` handling live in the
  auth callback, the proxy and the server actions, which the page does not
  touch. The page still pushes `/dashboard` and refreshes the router exactly
  as before.
- `AuthShell` and `LoginForm` cover the card, the Google button, the divider,
  the fields, the alert line and the mode toggle with 44px targets.

## Tests that changed meaning

- "Shows an inline field error ... when the email field is empty" is now
  "asks for an email and sends no reset email": the assertion checks the
  alert line and `aria-invalid` instead of the `email-error` id and
  `aria-describedby` (gap 4). The no-reset-call and no-toast assertions are kept.
